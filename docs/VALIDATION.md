# 验证记录 · 2026-11-02

初始测试环境：Linux 容器，Node v24.19.0、Python 3.12.14、预装 Chromium。初始原型无依赖安装；后续加入跨平台 Node 静态构建与 CI，见 README。所有命令在项目根目录执行。

## 已实际执行

- `npm test`：15/15 通过，0 失败，最后一轮约 3.39 秒。覆盖 44.1k/48k 的合成泛音单音（MIDI 40/45/52/64/65/67/76）、静音/噪声、C/Am 候选与非候选七和弦拒绝、PCM 起音到八音短谱对齐、缺音、重复音、匀速变化、未知/额外音因果策略、削波、已知连续换音失败、DC 保留原始波形、噪声强度对照、取消授权请求后晚到音轨释放。
- `npm run fixtures`：生成六个实际 PCM16 WAV 到 `fixtures/`，包括 melody、c_major、noise、missing、repeated、unsupported_chord。文件被 gitignore，生成器纳入项目。旋律默认音间距 1 秒，即该每音两拍短谱的 120 BPM 测试版；课程草案中的 60 BPM 不被测试固定为评分速度。
- `node scripts/browser-smoke.js`：6 个检查均通过。页面生成 PCM 经 Worker 得到 8 个音并完成对齐；C 候选识别；本地缺音 WAV 经浏览器 decodeAudioData 后得到 7 个音和一个 unobserved；Chromium 假麦克风经 getUserMedia → AudioWorklet → Worker → 实时跟随 → 停止；权限拒绝路径；无页面运行时异常。浏览器使用假麦克风 WAV，不是实际硬件。
- `node scripts/noise-benchmark.js`：14 组原始/预处理对照已完成，原始数值见 `noise-benchmark.json`。这不是只喂已知音符事件的测试：音高、起音、和弦都从 PCM 开始计算。

## 抗噪结果与解释

对照为固定随机种子的平稳噪声，SNR 20/10/0/-5 dB，另有 DC 偏移与调性伴奏混入；干净单音包含二、三次谐波，不只纯正弦。和弦测试仍是理想叠加纯音，尚不足以代表真实扫弦。

干净/20/10 dB 的四个稳态单音样本均无音高错误或八度错误。0/-5 dB 的四个样本全部变成未知，说明拒识增加，不是噪声问题已经解决。干净旋律 4 个起音都匹配，平均绝对偏移约 12 ms；20/10 dB 只有 3 个起音达到可信且音高匹配标准。DC+10 dB 的原始路径只检测出 1 个起音，去均值后检测 4 个、可信匹配 3 个。此结果只支持去 DC 对该样本有效。

预处理在强噪声下把候选和弦变为未知，减少了信心但也损失了一个本来猜对的结果，不能据此宣称和弦准确率提升。对照使用由生成过程已知的噪声 RMS，是理想背景估计；实际 UI 的背景测量、变动人声和真实伴奏尚未验证。本次没有真实人声录音，也没有训练或集成神经网络。

每组（稳态音、和弦、约 2.9 秒旋律）的运行墙钟耗时约 83–359 ms；这受机器、JIT、门控跳过计算影响，不是可泛化的手机 CPU 基准或音频链路延迟。启用去均值不增加前视窗口；单音/和弦原有 85/341 ms 窗口与输入输出链路延迟仍然存在。

## 明确未验证 / 已知限制

- 真实琴/麦克风/USB/板载硬件、物理拔线恢复、跨浏览器与手机性能尚未验证。自动测试中的取消和拒绝权限不等于全部设备生命周期已验证。
- 连续等响度换音是已固定的失败样例；快速重复、轻拨、连音会漏起音。离线缺失称 unobserved，不假装知道漏弹。
- 只有有限候选和弦，没有实际扫弦、转位、任意复音或弦品诊断保障。未知和弦仍可能误匹配候选。
- 对齐是因果贪心 / 离线编辑距离 baseline；局部速度变化、重复音歧义、重奏/反复、大幅跳段未解决。平均 BPM 不代表节奏评分；无链路校准。
- 文件适配只分析第一声道、最长 60 秒；没有录音保存或上传功能。浏览器解码格式随实现而异，错误会显示。
- 教学 UI、课程状态机、跟弹→填空→盲弹流程、复习存储本轮按更新后的优先级暂缓，只保留设计。

下一轮先收集带时间与音高标注的真实琴录音，增加噪声/人声/伴奏/弱音集，比较起音覆盖、错误音、八度错误和 unknown，再决定更复杂的检测或音乐专用降噪是否值得引入。
