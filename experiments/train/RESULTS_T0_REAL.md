# T0 冻结模型：真实录音开发诊断失败

结论：原始 120 步数学谐波 toy 模型不能用于实际音高识别，不上线。此处记录由独立评测环境提供的脱敏结果，本代码环境没有重跑真实音频。完整 18 条结果、输入/模型/脚本/配置哈希和分母见 [results-t0-real.json](results-t0-real.json)。没有重训、调整门限或替换原权重。

|---|---:|---:|---:|
| 已知单音区域的半音分类正确率（不经过 activity 门控） | 9.72% | 9.05% | 10.39% |
| activity 门控后的分类正确率（分母仍为全部 eligible mono） | 4.76% | 3.02% | 6.51% |

| 无音区域误报率 | 6.79% | 4.15% | 9.43% |
| activity F1 | 71.97% | 59.78% | 84.16% |

Activity 判断是否存在目标吉他，包括可靠标注的复音；pitch 只评价 eligible 单音。**Activity F1 不是音高准确率**，两者分母不同。各录音等权；极少单音帧的 comp 仍保留，不能把相邻帧当独立实验样本。oracleMono 指评价时用标签选单音区域，不代表可部署 oracle 或模型能识别单音/复音。

N1 room-only 的不门控/门控 pitch 为 25.50%/9.44%；加入朗读为 26.91%/14.66%，再加入瞬态为 26.31%/16.27%。单场景中分数上升不证明抗噪性。三个负例（讲话、瞬态、二者组合）的 activity 误报率分别为 15.12%、5.74%、15.24%。没有冻结事件解码器，所有 eventF1 为 null，不报告音符事件 F1。

原始训练代码为 `cbdc9a1ef984058f8faf321c058483e7be411b03`，ONNX SHA256 为 `82c51d63b7504f02c48b4adee5a7b384e3dfb5a6a5a914db8af9cb41527f11b3`。ORT 1.22.0 导出的固定两段输入在 1.23.2 CPU 下 logits/PCM state/feature state parity 通过，最大 logits 差约 7.63e-6（固定 atol/rtol 1e-4）。这是数值一致性证据，不是识别质量证据。

使用 16 kHz、256 hop、1024 尾随窗；每录音重置状态，前 3 hop 无效，尾部非整 hop 丢弃并记录。网格取最近已可用 hop-end，不向未来插值；重采样离线完成。原模型保留旧训练标签/loss/chunk 问题，推理仅使用正整数 hop，未调用训练 loss；源码后续修复不改变本次权重。无精细 F0/调音输出。

R1 已看过，只是开发诊断；N1 为一段采样吉他、一个合成房间与真实朗读/瞬态素材，不是现场谈话或泛化测试。MIDI gate 与声学起音/释放存在差异。R1 wall 3.56 s、N1 0.59 s 是单次共享 CPU 运行，不能当浏览器/音频设备端到端延迟。完整私有预测仍在独立评测环境；公开仓库只保存摘要和协议，评测脚本目前仅有提供方哈希，未冒称公开可一键重现整个评测。

下一步先做 T1 本地数据接入、来源/增强分组防泄漏、可靠标签与负例校验。R1/R2 不再标为 untouched test；N1 不用于训练。后续训练预算和 real-only / synth+real / augmentation 对照另行冻结，当前不启动长期训练，不更换线上 DSP。
